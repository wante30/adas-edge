# RK3566 真实 PCIe 整机性能优化与 FAST-Q4 验收

日期：2026-11-02。基线：`a9054ec21fb4a97637f06bbf0ece1d36f0f08c2e`。优化分支：`perf/real-pcie-fast-q4-20261102`。物理前向源 Q4。原版目录和二进制均已保留。

## 已交付的代码变化

- 新增正式 FAST-Q4 菜单项，复用 FAST-MOSAIC 的 BDD INT8 512×288 C API、9 输出/3 尺度及原动态库。输入只从 packed RGB565 提取 Q4 的 640×360 区域，避免额外全帧 RGB888 解码。Q2 OCR 独立保留。
- 模型切换递增 epoch，真实 APPLIED 后才接受对应模型结果。检测坐标复用 Q4→ROAD 1280×720→危险事件/Tesla 的既有路径。MTL 默认未更换；FAST-Q4 不补跑 MTL、不继承旧道路语义或掩码。
- 用原生 Qt Scene Graph 绘制目标矩形和缓存文字纹理。Tesla 与框层直接消费同一 C++ 检测快照，减少 QVariantList→JS→C++ 往返；按实际变化分别通知模型、导航和信号属性，交通灯置信度在 C++ 计算。
- OCR 改为最新请求覆盖、局部卡片差分、真实时间戳 freshness、单线程 ORT/OpenCV，并收窄距离行 ROI。AI OpenCV 保留原先 4 线程，因为实测改成 1 会降低四路吞吐。未降低模型输入高度或更换 OCR 权重。
- 跟踪候选在 NumPy 中过滤后进入 Python，保留原匹配顺序；跳过无活动轨迹的空摄像头。MTL RGBA 着色改为查表，颜色和掩码逐字节等价。
- 新增按相关进程采样的 /proc profiler、线程运行/排队时间、PGV 读/CRC/上传计时、真实菜单验收、独立日志审计、恢复与运行包来源校验。

没有修改 FPGA RTL、PCIe 驱动、RKNN Runtime、模型权重或量化结果。真实 CRC 始终开启。自动制动发送授权始终关闭，状态机、控制决策日志、真实 LVT1/HUD 均保留。

## 测量口径

板端墙上时钟错误地显示 2024 年，所有耗时、窗口、帧龄和完成率采用 monotonic 时钟。CPU 总占用以四核合计 100%；进程/线程占用以单核 100%。

Qt 完整平均使用相邻 HMI monotonic 采样间隔加权，包括模型切换与卡顿。Qt p10/p50/p95 是采样 FPS 分布。AI FPS 按每个 bridge/epoch 的真实结果完成间隔计算，再累加 intervals/seconds；没有用最近一帧 pipeline 耗时的倒数代替完成 FPS。稳态剔除每段开始 10 秒和结束 2 秒，其与完整窗口分别列出。

顶部“视频 FPS”是 HMI 接收源帧率，不能当作 Scene Graph FPS。FPGA frame_id 增量只能说明观察到的源序号推进率，没有独立测量 FPGA 时钟。NPU 驱动负载在关闭 AI 的诊断中也报告 100%，疑似保持的状态值，不能据此声称 NPU 全时满载。

## 基线 A/B/C/D 与剩余瓶颈

修正采样器后的基线 `baseline2_*`：同一真实 PCIe、相同 governor 与采样口径，每项约 40 秒。动态视频内容随时间变化，因此这是同配置顺序 A/B，不能视为逐帧相同负载。

| 基线组合 | Qt 采样均值 FPS | 纹理 FPS | 接收源 FPS | MTL 完成 FPS | 四核 CPU | GUI 更新 ms |
|---|---:|---:|---:|---:|---:|---:|
| A 视频，AI/OCR 关闭（仅诊断） | 48.98 | 42.62 | 53.97 | — | 71.10% | 8.20 |
| B AI，OCR 关闭（仅诊断） | 26.35 | 24.86 | 47.11 | 6.439 | 86.71% | 39.28 |
| C 完整功能 | 18.62 | 17.78 | 41.13 | 6.182 | 95.20% | 54.44 |
| D C + Tesla 动态目标关闭（仅诊断） | 19.36 | 18.71 | 42.64 | 6.176 | 94.49% | 49.57 |

A 说明完整视频链路本身具有超过 28 FPS 的能力，但同时引入 AI/OCR 后 CPU 接近饱和。B→C 的下降比 C→D 大，OCR/调度竞争比 Tesla 动态目标更明显。PCIe 采集约占一个核心，原 OCR 的多个线程合计也接近一个核心；GUI 和 RenderThread、源读取、跟踪共享余下资源。

采样器早期遍历所有内核 task，开销约 40% 单核；已修正为只采样相关 PID。早期 `baseline_*` 和错误 QML 的 D 不用于结论。cProfile 的输出单独作为热点诊断，不用于正式 FPS 对比。优先级试验受 PCIe 掉线影响，无效；关闭全部 QML layer 没改善 Qt，未保留。NPU performance/900 MHz 的短试验收益有限，最终恢复原 governor；另外发现 NPU 在试验后保持 900MHz，故额外显式恢复 600MHz，并从全新解压目录重新进行完整长测。900MHz 的完整窗口单独标注，不能计作同频率代码优化收益。

PGVF 路径：DMA snapshot 到缓存内存→校验/释放 lease→原子发布 PGVF→HMI pread+CRC→共享帧槽→MFR1 提供 AI→RGB565 GL 上传。线程分工使接收源快于实际显示：GUI/渲染受 CPU 排队影响，最新帧替换并合并唤醒；“接收 40+、显示 20+”不能解释为纹理带宽单项上限。没有关闭 CRC，也没有把旧帧重复渲染当作新视频帧。完整 Qt Scene Graph 仍可能渲染没有新纹理的界面帧，因此同时提供独立上传计数率。

本轮没有采集硬件内存带宽计数器或逐次 mutex 竞争事件，不能把 wall/CPU 的全部差值都归因于锁或带宽；线程 schedstat 的 runqueue wait 明确表示可运行却未获 CPU 的等待，NPU call 的 wall 则也包含设备执行等待。

此前 45 秒采样中 RenderThread 实际运行约 16.3 秒、排队约 14.5 秒，HMI 相关线程合计运行约 21.8 秒、排队约 34.1 秒。最终长测的线程运行与排队总量另见下面表格及 JSON。分项时间为测得的 wall 或 thread CPU 时间，二者不会混算。

## OCR 与等价性验证

24 张真实 Q2 小样本经人工逐张读取距离。原 ROI+320 宽度 21 张 valid，其中 10 张距离正确；新 ROI+128 同样 21 张 valid，21 张距离正确，另 3 张仍不可读。新 ROI 的 320/128 两种宽度在这 24 张的距离/方向/valid 一致。独立平均耗时约 549→270 ms。它证明本批距离 ROI 修正有效，不能据此推断通用 OCR 准确率。

真实整机 OCR 状态统计是结果快照有效率，包含同一 OCR 结果复用；不能与独立 OCR 识别成功率混为一谈。

板端等价性微基准：候选关联过滤 10.946→0.132 ms；MTL RGBA 9.701→4.381 ms。测试验证候选顺序/匹配和全部类别的颜色输出等价。微基准收益不等于整机 FPS 的同等倍数增长。

独立 C API 使用 CRC 通过的真实 PCIe 固定快照、无 Qt/OCR，每种 5 次预热+50 次测量：FAST-Q4 40.939 FPS，FAST-MOSAIC 31.783 FPS。二者 NPU call 均约 13.5 ms，因为模型输入张量相同；主要差别在裁剪/转换/前处理（约 6.4 vs 12.6 ms）。这不是整机正式成绩；该独立基准没有同步逐样本频率日志，不能用它推断不同频率下的吞吐。

### 功能与完整性

真实采集计数率 45.319 FPS，HMI 接收累计计数率 43.797 FPS；FPGA frame_id 观察推进率 60.000/s。源序号丢帧计数增加 9888，CRC 错误增加 0。源序号跳跃和最新帧显示调度造成的视频丢帧必须如实保留，不能记作零丢帧。

独立审计：采集/LVT1 离线采样 0/0；错误前向源 0；FAST-Q4 残留 MTL 0；1969 个危险框的 event_id/severity 不匹配 0。有 19 个 UI 快照保留了当时无对应可绘制框的事件（事件生命周期与当前检测框数量不保证一一相等），该数单独记录而未隐藏。

控制发送请求 0；关键事件决策原因：`{"control_not_authorized": 129}`。没有用 DRY_RUN 或 ACK 代替机械制动实测。

危险事件类型计数：`{"VEHICLE_CUT_IN": 227, "PEDESTRIAN_IN_PATH": 260, "FRONT_COLLISION_RISK": 266, "PEDESTRIAN_NEAR_CROSSWALK": 42, "PEDESTRIAN_CROSSING_PATH": 8}`。

OCR 结果快照状态：`{"UNREADABLE": 407, "VALID": 6377, "STALE": 25}`；VALID 占 93.66%。这包含结果复用，不是带真值的识别准确率。

### 目标判断

Qt 目标 ≥28，最终完整 22.710，**未达标**。MTL-FAST 目标 ≥6.5，最终全窗口 5.915，**未达标**。FAST-MOSAIC 目标 ≥13.8，最终全窗口 13.565，**未达标**。

FAST-Q4 稳态 14.295 FPS，为 MTL 的 2.41 倍，相对四路 5.5%。两者 NPU 输入尺寸相同，因此增益主要在前处理，不应预设裁剪后 NPU 必然大幅加速。

### 单独保留的 900MHz 窗口

`final610` 连续 612.236 秒功能检查通过，但实际 NPU 900MHz。完整 Qt 22.315 FPS；AI MTL/FAST-Q4/MOSAIC 6.263/14.639/14.049 FPS。这个结果单独保留，不作为恢复 600MHz 后的同频 A/B。

## 未解决的边界

开发前/期间 PCIe 两次出现 revision ff、capture_io 和 LVT1 离线，重启恢复；第二次约运行一小时后发生。故障记录保存在 evidence archive。未实现 PCIe 热恢复；本轮禁止修改驱动/RTL，也没有把重启恢复包装成根治。

FAST-Q4 保留为正式高速模式，MTL-FAST 仍为默认完整道路感知。实景截图可证明框/面板/BEV显示正常，但没有带标注检测真值集，不能对远处交通灯或行人的召回率作定量准确性结论。

本次四路实景截图中 Q1 为黑区。另对 CRC 通过的 PGVF 原始 payload 检查，Q1 的 230400 个 RGB565 像素全部为零，Q2/Q3/Q4 含非零数据（见 `source_quadrants.json`）。因此验收证明四宫格显示和全拼图推理/坐标路径工作，不能声称当前四个物理摄像头都有有效实时内容；应用没有用旧缩略图填充这个源黑区。
