# 原生前视事件预警原型

## 当前范围

复用冻结的 `yolo11n_512x288_split.onnx` 检测车辆和行人，不训练模型。原生测试台继续使用 Tesla-BevCam 的渲染入口。新增模块只依赖现有 NumPy/OpenCV，按源视频约 10 Hz 的主模型更新节奏工作。

这是一版 **PC 视频事件原型**，不是已经通过 RK3566 或 FPGA 验收的功能。明确区分：

| 输出 | 当前条件 | 能证明什么 |
|---|---|---|
| `LEAD_RAPID_CLOSING` | 假设路径内同一车辆连续放大、拟合稳定、相对背景扩张、横向偏移小、连续两次成立 | 单目图像快速逼近提示；不是前车真实减速度 |
| `LEAD_BRAKE_LAMP_RISE` | 当前/近两秒选中的车辆，成对红色灯区域相比前序图像变亮，连续两次成立 | 疑似制动灯外观变化，单独不会触发制动 |
| `SUSPECTED_BRAKING_WITH_CLOSING` | 同一车辆同时出现前两种线索 | 疑似制动且快速逼近；急刹车仍未确认 |
| `PEDESTRIAN_CROSSING_PATH` | 行人足点进入假设路径，扣除背景平移后的横向运动稳定，连续两次成立 | 行人横穿路径提示；不是违法状态 |

碰撞或行人路径危险通过 `FrontSnapshot.as_perception()` 接入现有策略，优先输出 `BRAKE` 和相应报警。制动灯提示不单独制动。车辆红灯从不用于证明行人闯红灯。

## 证据边界

- 急刹车状态保持 `UNKNOWN_NO_EGO_SPEED_OR_CALIBRATED_RANGE`。没有标定距离和本车运动数据，不能把本车加速/转向造成的相对运动认定为前车急减速。
- 行人闯红灯状态保持 `UNKNOWN_NO_ASSOCIATED_PEDESTRIAN_SIGNAL`。当前没有识别并关联到行人横穿方向的行人信号灯。
- 蓝色梯形是明确的图像路径假设，默认较窄；不是识别出的车道，不随模拟车道按键推断真实自车姿态。转弯/变道及其他相机位置可能漏报。可以在匹配视频 SHA 的场景配置中提供四个归一化 `hazard_path` 点，但配置不是识别结果。
- `visual_tau_s` 是检测框尺度变化的图像代理量。不是经过相机标定验证的真实 TTC，不能当作可靠的米、速度或减速度。
- 检测漏检、拥挤遮挡导致身份不明、图像运动不可靠时暂停事件判断。历史不能补成真实观测。背景暂缓不表示前方安全。
- 静止行人、纵向移动行人、骑车人危险尚未由本次“横穿行人”分支覆盖。不能把无事件输出解释成没有碰撞危险。
- 原生界面显示的是建议制动/PC 模拟状态，没有执行实际车辆制动，也没有写物理 PCIe 寄存器。

## 实现与保护

1. `image_motion.py` 在 320×180 灰度图上运行稀疏光流与 RANSAC 仿射拟合。屏蔽前后帧的动态检测区域和仪表台，检查背景分布与一致性。该结果是图像运动，不是里程计。
2. `image_tracks.py` 按类别及 IoU 做保守双向最佳匹配。歧义不继承身份，短时丢失最多保留 250 ms，每条历史最多 18 个观测。
3. `hazard_events.py` 检查源时间连续性；转弯、强缩放、画面切换/背景不明清除历史，至少等待 500 ms 恢复判断。连续两次事件确认只接受新源帧。
4. 灯光外观变化、图像路径假设、真实危险事件的确认程度分别写入 `trace.jsonl`，暂停、重播、打开新视频不能续用旧危险结果。危险显示有效期为 250 ms。

算法是为本项目编写的轻量原型，光流与仿射估计调用官方 OpenCV API；没有另外宣称移植某个完整开源急刹/违规识别模型。

参考：[OpenCV 光流接口](https://docs.opencv.org/4.5.4/dc/d6b/group__video__track.html)、[Mobileye FCW 的距离与相对速度说明](https://ims.mobileye.com/fleets/uk/technology/forward-collision-warning/)。

## 验证要求

- 软件测试覆盖连续逼近/横穿正例及正常跟车、后退、检测框抖动、镜头平移、统一缩放、路边车辆、骑车人、遮挡歧义、暂停/重播、过期结果等反例。正例是明确标记的软件夹具，不是真实视频准确率。
- 官方视频中的所有报警片段需要人工查看。开发早期的宽路径误选路边车辆问题须保留并记录，不能把输出事件数量当作正确事件数量。
- 用户已确认暂时没有急刹/闯红灯的明确正例视频。本轮完成现有官方视频回放与误报检查，保留正例真实性验证待完成。
- 上板需要把同一事件模块接在实际 RKNN 检测结果后，测量采集→推理→事件→显示/PCIe 的延迟和误漏报；PC 新增后处理时间不能替代这项验收。

结果目录：`C:\Users\JingyuWang\adas-edge\outputs\hazard_events_20261014`。以 `validation_summary.json`、`official_final` 和 `native_final` 为最终证据；`official_v1/v2/v3` 是保留的开发对照。
