## 实际重新运行的模型

最终检测证据使用 RKNN 构建对应的 **raw-head 浮点 ONNX 导出图**，不是旧 COCO 缓存，也不是板端 INT8 结果。

| 模型 | 本地导出图，相对于 `D:/Datasets/adas_edge_training` | 交通灯类别 |
|---|---|---:|
| FAST-Q4 / BDD | `rknn_b05o/bdd_yolov8n_512x288_raw_heads.onnx` | 8 |
| B05N P2 | `rknn_b05o/b05n_p2_multiclass_512x288_raw_heads_20261026.onnx` | 8 |
| B05L P2 Specialist | `rknn_b05o/b05l_v8n_p2_512x192_raw_heads_20261026.onnx` | 0 |
| MTL-FAST | `b05n_mtl_rknn_b2a_seg256_20261031/b05n_p2_mtl_b2a_seg256.onnx` | 8 |

RGB、归一化、letterbox、DFL 解码和类别 NMS 直接运行；主模型输入 512×288，Specialist 512×192、Q4 上方 60% ROI。原始视频先以 INTER_AREA 缩到 640×360，模拟 Q4 可用图像细节。所有模型的路径、SHA256、执行 provider、输入形状见 `offline_evidence_20261112/models.json` 和 `mtl_model.json`。

离线诊断统一使用 NMS IoU=0.45；旧 Specialist 运行包装器使用 0.70，因此这里不宣称调度、后处理和量化路径与实机逐位一致。原图属性分支是高分辨率参考上限，不是实机 Q4 可以直接取得的细节；JSON 标记 `source_video_native_reference`。

中途发现较早的 BDD split 图与部署 raw-head 导出图有 2/63 个卷积张量不同，因此废弃其作为最终检测依据，重新跑了最终 raw-head 图。P2 和 Specialist 的旧 split/decoded 图分别与 raw 图 78/78、74/74 个卷积张量一致；最终同样切换为 raw 图。中间结果保留在 outputs 下，最终证据目录在下文明确列出。

## 检测：框口径与真实漏检分开

检测阈值保持 0.25，没有为提高召回直接降低部署阈值。严格灯头 IoU≥0.5 和灯面覆盖率是两种不同指标，不能互换。

灯面定位定义：预测框覆盖至少 50% 人工发光灯面，中心位于人工灯头内，预测面积在 0.25×灯面面积至 1.5×灯头面积之间；一对一匹配。它反映是否取得可分析灯光的 ROI，**不代表正确检测出整个灯头**。

| 模型 | 红灯：严格灯头 IoU | 红灯：灯面定位 | 绿灯：严格灯头 IoU | 绿灯：灯面定位 |
|---|---:|---:|---:|---:|
| BDD / FAST-Q4 浮点对应图 | 1/6 | 1/6 | 1/6 | 3/6 |
| B05N P2 | 0/6 | 2/6 | 0/6 | 4/6 |
| B05L Specialist | 0/6 | 0/6 | 0/6 | 2/6 |
| MTL-FAST | 0/6 | 0/6 | 0/6 | 2/6 |

P2 在红灯第 30、90 帧框到的是左侧亮灯灯面，不是整个横向三联头，所以严格灯头指标为零，而灯面定位为 2/6。MTL 对红箭头的召回同样不足。属性算法不能补救没有候选框的灯。

历史绿灯 **1/6** 的解释：只为追溯旧统计而重评旧 COCO+旧 Specialist 缓存，旧灯头 IoU 是 1/6，本次人工灯面覆盖口径是 5/6。旧数字受灯面/灯头框语义、很小框的 IoU 和旧真值边界偏差共同影响，不能将其直接写成“属性分类只有 1/6”。这份历史缓存不参与本轮新模型结果；新模型的 3/6、4/6 也不应与旧 1/6 直接作提升百分比比较。

BDD 在绿灯的阈值诊断：灯面定位 0.25 时 3/6，0.15 时 6/6；但没有全场景负样本真值来量化新增误检，所以**只记录阈值敏感性，不修改线上阈值**。中心裁剪放大、上方 60% 和原图直接缩放均未稳定提高召回，见 `detection_ablation.json`。

## 颜色与箭头：独立人工 ROI 对照

下表全部使用人工 ROI，检测漏检不进入属性错误分母。UNKNOWN 计作未正确识别，同时单独记录；不只报告已知输出的准确率。

| 样本和输入 | 颜色：PR #13 → 本轮 | 箭头/形状：PR #13 → 本轮 |
|---|---:|---:|
| 红灯原始 1080p，6 ROI | 2/6 → **6/6** | 箭头 1/6 → **6/6** |
| 同帧缩为 Q4，6 ROI | 2/6 → **6/6** | 箭头 0/6 → **0/6**，全部 UNKNOWN |
| 绿灯原始 1080p，6 ROI | 6/6 → **6/6** | ROUND 0/6 → **5/6**，1 个 UNKNOWN |
| 同帧 Q4，6 ROI | 6/6 → **6/6** | ROUND 0/6 → **0/6** |
| 原 15 张照片，已知真值 | 24/32 → **25/32** | 所有形状 9/31 → **11/31**；其中箭头 **7/16 → 7/16** |
| 新 3 张混合照片，原始像素 | **8/8** | 所有形状 **5/8**；箭头 **2/3** |

原照片和新照片本轮的属性错误均为 UNKNOWN，没有与真值不同的已知颜色/方向输出；样本太少，不能据此宣称误判率为零。原照片已用于先前开发，不能当独立测试集。原 33 ROI 含 1 个颜色 UNKNOWN 真值和 2 个形状 UNKNOWN 真值，因此分母分别是 32 和 31。

以前红视频颜色 **2/5**、箭头 **0/5** 是“匹配且有效的跟踪结果”分母。现在 6 个真值 ROI 绕过检测，和旧有效轨迹的 5 个分母不同。两种报告均保留，不能把 2/5→6/6 直接当同口径提升。

### 可修复错误及代码变化

1. **偏洋红的红 LED 被 HSV 截掉。** 原范围 H≥170，真实视频中直行红箭头大量像素在 H=160–169。仅在独立多灯后端扩展到 H≥160，颜色掩模与形状掩模保持一致；旧全局 HUD 颜色函数未修改。没有使用目标位置判断箭头。
2. **绿色背景/反光污染圆灯轮廓。** 默认箭头流程不变；只在绿灯形状 UNKNOWN 时额外尝试相对亮度 LED 核心提取，且仅允许恢复 ROUND。该分支不输出新箭头方向，避免阈值切断细杆后误认箭头。原照片 ROUND 增加 2 个正确，箭头 7/16 未退步。
3. **OpenCV 自交轮廓异常。** 原生绿灯样本触发 convexityDefects 异常。现在返回 `INVALID_GLOW_CONTOUR`，不让一个 ROI 终止整段离线视频。开运算清空轮廓时也返回明确 UNKNOWN。

### 仍然失败的具体样本

- **Q4 红箭头**：发光区域约 8–10 像素，原始视频约 24–30 像素。全为 `INSUFFICIENT_SHAPE_PIXELS`。原视频看清不代表真实 Q4 仍有同样细节；放大显示或插值不能作为新证据。
- **牛街红左箭头**：原始发光轮廓约 22×25，有 303 个颜色像素，肉眼方向明确；LEFT 模板 0.643、STRAIGHT 0.639，差值仅 0.004，返回 `AMBIGUOUS_SHAPE_TEMPLATE`。这是清晰样本中的模板泛化不足，不能归咎于远距离。裁剪及详细证据见 `offline_evidence_20261112/clear_arrow_template_failure.*`。
- **绿灯 60 帧右头**：原图也有杆件/反射干扰，保留 UNKNOWN。其余 5 个原图圆灯可恢复；Q4 主要仍是像素不足或轮廓污染。
- 原照片还有暗灯、失焦、细 LED 离散结构、透视变形、紧裁剪、模糊右箭头等错误；每个失败 ROI 有 PNG 与 JSON，保留颜色计数、glow bbox、模板得分及原因。
- 将 ROI 分析上限由 192 改为 384/768 的离线对照，原照片箭头从 7/16 变为 6/16，没有改善；保持默认上限。不能只把阈值放宽当成“修复”。

## 多灯输出与关联

新取得同一曝光的 Montreal 照片包含 **红圆灯＋绿左箭头＋红圆灯**：人工 ROI 在原图和 Q4 都分别得到三条正确信号，`observed_directions.left=GREEN`，另外两个方向 UNKNOWN。红圆灯没有被解释成“直行红灯”。

Jeffrey Road 照片包含红左箭头及两组绿色圆灯：原图识别红左箭头和至少一个绿圆灯。牛街照片包含红左箭头和绿圆灯，颜色独立正确，但箭头模板拒识。所有照片也重新运行了整图 BDD/P2，检测路径与人工 ROI 路径在 JSONL 中分开：Montreal 横向多面灯甚至没有达到 0.25 的整图候选，**人工 ROI 成功不等于 YOLO 端到端成功**。

已知可见方向关联（不含本车道路归属）：红原图 6/6，Q4 0/6；新混合照片原图 2/3、Q4 1/3。未经支持的方向继续 UNKNOWN，新照片原图 6/6、Q4 6/6。全部 3 张新照片的本车道路方向保持 UNKNOWN，不把这一项写成“正向车道关联准确率 100%”。

仍缺少带可靠道路归属真值、**绿左箭头＋红直箭头**及左/直/右三方向同曝光的充足真实路口样本。因此本轮没有完成正向本车车道关联验收，也没有用圆灯、照片横坐标或导航标志凑出这些样本。独立颜色、视觉箭头和本车道路关联仍是三个不同字段。

## 传统方法还值得投入多少

**已测得的提升**：这段红视频的人工原图颜色补回 4/6、箭头补回 5/6；Q4 颜色补回 4/6，箭头没有提升；原照片箭头仍 7/16。另恢复了部分绿色圆灯。不能把红片 6/6 外推到其他路口，也没有可信依据宣称还能固定提升 10% 或 20%。

**判断**：传统算法还有少量明确工程问题可修，但现在继续大规模堆模板/调阈值的投入回报已经偏低。清晰牛街样本仍无法拉开方向模板差距、真实杂图箭头仅 43.75%，且提高 ROI 上限和改变检测裁剪不稳定，已经值得训练专用轻量 CNN 作为箭头后端的下一轮原型。此次没有训练或接入第二网络。

建议下一步：

1. 优先补采 **原始 Q4** 的真实 ROI，同时保存高分辨率参考；按路口/拍摄序列分组切分训练验证，避免相邻帧泄漏。已有 41 ROI 远不足以训练可交付模型。
2. 使用 32×32 或 48×48 的小型深度可分离 CNN 作为实验起点；类别包括 ROUND、左/直/右/掉头、UNKNOWN/不可辨，另覆盖行人灯、倒计时、暗灯、多灯混合等负样本。颜色继续独立 HSV，对比后再决定是否多头学习。
3. 同一批人工 ROI 比较传统后端与 CNN 的正确率、拒识率和错误已知方向率；必须单列小像素组，不预设 CNN 能恢复 8 像素灯面的可靠方向。
4. 同步解决检测召回和框语义。CNN 只分类已有 ROI，不能补回红箭头的主模型漏检，也不能解决本车道路关联。训练结论需要独立路口测试集支持。
5. CNN 保持 `AttributeBackend.classify` 输出结构，未来 FPGA ROI 分类器仍可替换；此轮硬件接口和控制逻辑完全未变。

## 复现与交付位置

安装 PC 侧 numpy、opencv-python、onnxruntime。以下命令均在仓库根目录运行，使用新的输出目录保护既有证据：

```powershell
python tools/evaluate_signals_offline.py --output outputs/repro_raw --clips 112454 113421 112507 113452
python tools/evaluate_signals_offline.py --output outputs/repro_mtl --models mtl --clips 112454 113421
python tools/evaluate_signals_offline.py --output outputs/repro_extra --models bdd --clips 112739 113343 113539 --stride 15
python tools/report_signal_diagnostics.py --input outputs/repro_raw --output outputs/repro_reviewed
python tools/fetch_offline_mixed_photos.py
python tools/evaluate_mixed_signal_photos.py --output outputs/repro_photos
python tools/ablate_signal_inputs.py --output outputs/repro_ablations
```

原照片可按既有 `collect_signal_photos.py --manifest docs/multi_signal/photo_sources.json` 的精确 URL/哈希恢复；比赛原视频保留本地路径，需要已有参考素材。源码不包含模型权重。
