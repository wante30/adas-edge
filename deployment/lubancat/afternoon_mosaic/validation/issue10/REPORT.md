# Issue #10：Tesla BEV 车辆跳动修复与 RK3566 回放验收

采集与开发：2026-11-02 至 2026-11-03（主机时间，UTC+8）。唯一开发基线：PR #8 `46400aa1a3610fe6537e0c2962ff991238e70c0d`。独立分支 `fix/issue10-bev-stability-20261102`。

本次在真实 RK3566 上编译、部署并运行 Qt 与 RKNN，输入为本地 Q4 录像回放。**没有真实 PCIe，本次不包含 FPGA ACK、机械制动或 PCIe 恢复验收。** FPGA、风险决策与原始测量路径没有代码修改；回放会话显式使用 DRY_RUN，不构造硬件反馈。

## 实现和根因

第一阶段提交 `51319450`：BEV 仅接收 `isTracked=true`、正 `serverTrackId`、匹配 Q4 和当前 tracker epoch 的测量。保留其他模块原有 `trackId` 与 2D 框，检测序号占位 ID 不再成为 3D 身份。sourceKey 同时隔离输入、模型、模式、前向象限和 tracker epoch。C++ fallback 仍服务原 2D 路径，缺少服务器身份的 fallback 框不进入 BEV。

取消差分速度外推；改用增益为 5/s 的指数插值，允许约 1.0 秒短暂缺测保持，后段渐隐。保留的历史位置只在渲染器内存在，不产生新检测、不进入风险事件或控制状态。修复 QML 同名 `sceneEnabled` 遮蔽上下文属性，以及 imperative visible 破坏可见性绑定的问题。

先测试这个最小修复，仍观察到较大的深度变化，因此第二阶段提交 `04057102` 增加三次观测中位数与按测量时间间隔的目标更新限幅，并按每次实际渲染的 monotonic 时间积分。限幅为横向 4、纵向 12 个**相对展示单位/秒**，不是车辆物理速度或米/秒；异常大变化还会受到每次更新 dt≤0.25s 的限制。

Python ByteTracker 在 Kalman correct 后仍保留原始 bbox，此次没有改变其输出、关联、风险用框或控制。平滑状态集中在 `hmi/bev_display_state.h`。没有更改模型精度、输入尺寸、权重、FPGA/PCIe 驱动，也没有添加每帧 Python 计算或图像重编码。原生渲染诊断默认关闭，身份计数仅在启用诊断时分配，并按 source epoch 清理。

查阅了干净的 Windows 稳定工作区 `adas-edge-hmi-stable`，相关 renderer 文件最后修改提交为 `fe794cbe5c97f2e815db5a26e82c02a3f81728f3`；其脚点/对数尺寸、更新限幅与指数插值提供了参考。也检查了仓库旧 Qt renderer 的低增益无外推策略。没有将早期 Qt 文件称为完整 Windows 源码，也没有宣称重新运行了 Windows 版本。本轮没有移植几何重关联或重新标定三维深度。

## 同输入 A/B 方法

1. RK3566 上用 PR #8 的 Qt/AI 处理 `/home/cat/qt_gpu_probe_ai_20261019/local_quad_full.rgb`，Q4 前向，运行 70 秒，选择真实 FAST-Q4 后端。源文件为已有 1280×720 RGB565 四宫格录像，1350 帧。eMMC 原始读取会限制推进速度，因此 70 秒运行不等于 70 秒新的道路内容。
2. 记录 Qt 实际收到的 bbox、真实服务器 ID、来源、原始采集时间和到达时间。原始 AI 输出及 inference epoch 一同保存在 evidence archive 中。
3. 验证工具 `bev_replay_main.cpp` 将同一份记录、相同的测量间隔和原始 Q4 视频帧送进板端的真实 Qt/OpenGL renderer。只平移 monotonic 时间原点，不改变 bbox、置信度或 tracker ID。新版本的隔离播放器 epoch 单独标记，不冒充原 AI epoch。
4. 对旧版、最小修复、深度鲁棒修复及最终版分别实录。旧版仅加入相同的可选诊断与共同 QML 激活修复，运动公式不变。比较不是另写的 Python 渲染动画，也不是伪造检测结果。
5. 导出的 `trajectory_csv.zip` 共 47,594 行，含原始采集时间、播放器采集时间、serverTrackId/sourceId、原 AI epoch、播放器 epoch、bbox/宽度、raw/filtered BEV、birth_count、visual dt 和测量年龄。两版的时间偏移由全部 bbox 唯一匹配核验；没有缺失原 AI epoch。原始 JSONL 未被修改，另存于 `raw_evidence.zip`。

原始时序图像、元数据和诊断路径见 [原始证据](raw_evidence.zip)、[CSV 轨迹](trajectory_csv.zip)、[机器可读结果](exact_final_analysis.json)及[时间对应与性能统计](performance_summary.json)。

## 车辆连续性与运动结果

以下只对同一个真实 serverTrackId、同 sourceKey、同一次可视生命周期的相邻渲染计算位移，排除 >150ms 的间隔。位移除以实际渲染间隔，再归一到 60Hz；单位是相对 BEV 单位，**不是米或米/秒**。各版本采样数不同，原始分母和全部分布均在 JSON 中。

| 指标 | PR #8 | 最小修复 | 最终修复 |
|---|---:|---:|---:|
| 实录轨迹时长，秒 | 68.83 | 69.23 | 69.22 |
| 真实 tracker 身份数 | 152 | 152 | 152 |
| 渲染的无真实 ID 占位身份数 | 22 | 0 | 0 |
| 真实身份重新创建次数 | 27 | 2 | 2 |
| 全部重新创建次数，含占位 ID | 235 | 2 | 2 |
| 60Hz 归一位移 p95 | 0.703 | 0.272 | 0.142 |
| 60Hz 归一位移 p99 | 1.738 | 0.589 | 0.228 |
| 60Hz 归一位移最大值 | 5.222 | 2.377 | 0.346 |
| >0.5 的位移尖峰次数 | 1351 | 335 | 0 |
| >1.0 的位移尖峰次数 | 555 | 64 | 0 |
| 保持超过 0.6s 的历史对象渲染行 | 0 | 3538 | 3267 |

最终 p99 尖峰降低约 86.9%，最大尖峰降低约 93.4%。剩余 2 次重建没有删掉或包装成零闪烁。这里证明的是相同 tracker 身份在展示层的稳定性，不等于有人工真值的物理车辆 ID-switch 评测；上游 tracker 的身份错误仍可能存在。

代价：指数插值时间常数约 0.2 秒，阶跃达到 90% 约需 0.46 秒；中位数增加约一个到达 GUI 的观测间隔。持续的大幅深度变化还会因限幅而延后，不能保证固定的最大显示延迟。最终显示对原始噪声深度的偏差 p95 为 10.55 相对单位；这不是深度准确率或物理定位误差。所有这些延迟只影响 BEV 展示，风险与 FPGA 输入仍使用原测量。

## 完整车机与性能

另用源文件前 600 帧逐字节复制为 RAM 回放，60FPS、10 秒内容循环，避免两版受 eMMC 冷热缓存影响。两次完整车机会话各 90 秒，执行相同 FAST-Q4→四路→单路→MTL-FAST→FAST-Q4 序列。未关闭导航 OCR、风险事件或任何正常界面；性能采样时关闭额外 BEV 时序诊断和录屏。

| 模式 | 旧 Qt 加权 FPS | 新 Qt 加权 FPS | 旧 AI 实际完成 FPS | 新 AI 实际完成 FPS |
|---|---:|---:|---:|---:|
| FAST-Q4 | 42.37 | 47.24 | 16.79 | 16.74 |
| FAST-MOSAIC | 44.44 | 48.32 | 14.58 | 14.31 |
| MTL-FAST | 41.58 | 44.54 | 6.73 | 6.41 |

Qt 用相邻 HMI monotonic 间隔加权；AI 用同 epoch 的 infer_end_ns 完成间隔统计，不以单帧耗时倒数代替。窗口剔除启动和切换区间；四路只有约 4.8 秒、MTL 约 13.8 秒稳态，不能当作长时正式成绩。完整窗口四核总 CPU 均值约 70.91%→66.64%，HMI 的 CPU 统计另列于 JSON。CPU/NPU 读取为 1.8GHz/600MHz，未调整 governor，但没有连续逐样本频率验证。

短 MTL 窗口约下降 4.8%，因此另外执行旧、新各 70 秒的 MTL 专项复核，结果见下方追加表。不得将上述表格写成所有 AI 模式均提速。本轮性能数据全部来自本地回放，不是 PCIe 整机性能成绩。


专项复核两版各运行 70 秒，取同样的第 10–50 秒稳态；后续执行证据压缩的区间没有用于此表，完整日志仍保留。

| MTL 专项 | PR #8 | 最终修复 |
|---|---:|---:|
| Qt 加权 FPS | 46.09 | 48.20 |
| AI 实际完成 FPS | 6.75 | 6.66 |
| HMI 四核归一 CPU | 24.12% | 25.11% |
| 整机四核总 CPU | 59.93% | 61.97% |

这一复核中 MTL 吞吐约下降 1.4%，Qt 约提高 4.6%，整机 CPU 多约 2.05 个百分点。有限次数的顺序回放没有显示明显吞吐回退，但没有多次随机顺序重复试验，不能证明所有输入和硬件场景性能等价。
