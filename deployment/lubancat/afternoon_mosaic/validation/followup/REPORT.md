# RK3566 后续版验收报告（2026-11-02）

## 结论与版本

基于 PR #6 的 `d397af411d592447197fa2f194144dca52c765dd`，实现单路/四路模型菜单、统一事件和黄红框、轻量规则、MTL 斑马线补充、非阻塞控制与 Windows ByteTrack-Lite / 原生 Tesla 平滑。源码验收提交为 `be56effd`；后续交付提交仅补充报告、文档和运行包。

**当前可通过回放完成的功能和性能检查通过。** 当前没有 PCIe 设备；控制仅为进程内 DRY_RUN，未使用模拟控制端口。真实车辆制动、LVT1 在线和 PCIe 断开重连尚未验证。原下午版目录、PR #6 及正式程序均保留，未修改 FPGA、驱动和 RKNN Runtime。

完整机器可读结论为 [FINAL_ACCEPTANCE.json](FINAL_ACCEPTANCE.json)。真实回放证据与合成事件证据分别归档。

## 同输入性能对照

同一份 1350 帧、1280×720 RGB565 录制，循环请求 60 FPS；单路 ROAD_Q1 使用 MTL-FAST，四路使用完整帧 FAST-MOSAIC。约 60 秒切换，最后四路窗口为 69.37 秒；完整窗口与单调时间戳均保存在原始验收 JSON。连续时间 **610.672 秒**。

AI 使用 PR #6 的实际完成计数：按 bridge/epoch/model 分组后汇总 `(n-1)/时间跨度`，并非界面瞬时 FPS，也不重复计同一结果。主对比使用测试区间全部完成；附带的原始运行报告另列排除 5 秒切换预热的稳态统计。Qt 使用整个区间全部 200 ms `scene_graph_fps` 行的均值，包含切换。

| 项目 | PR #6 | 本次 | 相对变化 |
|---|---:|---:|---:|
| FAST-MOSAIC | 14.534 FPS | 14.037 FPS | -3.41% |
| MTL-FAST | 6.899 FPS | 6.648 FPS | -3.65% |
| Qt 场景图 | 29.444 FPS | 28.095 FPS | -4.58% |
| 回放源 | 54.603 FPS | 58.014 FPS | +6.25% |
| CPU / 全部四核 | 23.856 % | 27.390 % | +14.81% |
| GPU 负载 | 36.239 % | 36.117 % | -0.34% |
| 驱动报告 NPU | 100.000 % | 100.000 % | +0.00% |

三项最低线 13.8 / 6.5 / 28 FPS 全部达到。Qt 仅高于底线约 0.095 FPS，新增负载余量较小；相对基线约下降 4.58%，没有把达到最低线表述成零性能成本。单路/四路稳态 Qt 均值分别为 28.985 / 27.434；判定采用基线的全程均值，不把单路或四路瞬时最低值替换成基线口径。

首两段与末两段完整窗口相比，单路完成率变化 -0.74%，四路 -0.65%，未见随时间持续衰减。CPU 较基线增加约 3.53 个四核百分比点。

## 性能开销与优化

快速数值规则按每次有效完成运行，后台只复用现有 MTL 掩码和最多三个车辆灯光裁剪，最新单槽、最多 2 Hz；没有恢复完整高频 RoadScene/HazardFusion，没有额外模型推理。

| 实测平均 / p95（ms） | 单路 | 四路 |
|---|---:|---:|
| RKNN 调用 | 78.719 / 84.713 | 15.845 / 18.095 |
| 主跟踪 | 12.229 / 21.782 | 11.961 / 20.782 |
| 快速危险层 | 2.171 / 4.152 | 1.499 / 2.755 |
| 状态组装 | 4.673 / 27.004 | 2.691 / 21.344 |
| 采集至发布 | 154.143 / 184.497 | 74.845 / 97.547 |

主要改动：把每次推理对 7×2048 条耗时样本重复排序，改为每秒汇总；保留每次完成运行规则。关联 IoU 矩阵采用 NumPy 批量计算。根据测得 GUI 忙碌比例调整请求退让，最多 8 ms，并保留 LEGACY 对照选项。短测优化前四路约 11.5 FPS，优化后长测为 14.04 FPS；这些不同轮次只用于说明瓶颈定位，正式基线仍为上表 PR #6。

独立 C API 的 25.61 FPS 不包括完整车机链路。本次四路 RKNN 均值 15.85 ms，主跟踪约 11.96 ms，另有帧写入/共享帧读取、状态与传输、Qt 和 OCR 的竞争，因此不能把裸 C API 数字当作整机帧率。

## 事件与控制实测

测试区间内有 963 条事件转换、246 条 CRITICAL 决策、73 次请求与 73 次进程内模拟 ACK，超时 0。所有 ACK 均为 `executed=false / simulated=true`。

风险确认至 GUI 更新：均值 112.88 ms，p95 204.54 ms；事件解除至框恢复：均值 117.97 ms，p95 204.40 ms。


框/事件身份或颜色不一致 0；WARNING 请求 0；CLEARED 请求 0；非 Q1 请求 0；缺失 CRITICAL 决策 0；重复发布 0；运行错误 0。两次短暂未匹配事件留在面板/日志，没有借用其他目标的框。GUI 用同一快照更新框、事件和控制结果，修复了接收线程完成下一帧时面板与框严重程度短暂错位的问题。

真实录制中出现了前向接近、切入、行人路径、斑马线附近行人、疑似制动灯变化等预警；本次真实 CRITICAL 为切入事件。不能把所有规则的合成通过写成全部规则已经在真实录像中识别出高风险。

## 运行包与明确限制

运行包和 SHA-256 / 逐文件清单位于仓库 `releases/adas_risk_control_20261102/`，源码、原生 HMI、独立四路 C API、脚本、配置、测试和证据一并提供。未包含巨型录制、模型和原系统 RKNN/Mali/Qt/OCR 安装。`config/baseline_launch.json` 不含 PID，可支持当前板无 PCIe 原 HMI 未启动时的回放启动；活动会话状态不会打包。

PCIe 断开必须重启的问题、真实 LVT1 在线、真实制动执行和硬件 ACK 兼容性，均需要设备恢复后测试。硬件适配器要求 ACK 回传 request_id；旧桥不回传时记录未匹配/超时。对向规则缺真实独立方向源；当前只验证方向条件的规则状态转换。图像路径为假定路径，BEV 为相对示意，不宣称标定距离和车速。Qt 性能余量小，增加额外负载后应复测。

运行包额外验证：[runtime_package_smoke.json](runtime_package_smoke.json)。从新目录解压，230 个文件 SHA 全部匹配，实际运行包内原生程序并收到 30 次新模型结果；随后恢复开发目录的 `delivered_replay` 回放。该验证在十分钟性能窗口之外进行。
