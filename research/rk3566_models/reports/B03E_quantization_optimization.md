# B-03E BDD YOLOv8n 阈值与 RKNN 量化优化

**结论：PARTIAL。** 成功完成四档阈值分析、一个 KL-divergence INT8 候选构建、RK3566 加载/输出检查和短时测速。KL 候选改善了总体 AP、Precision 和行人结果，但交通灯 Recall 下降，因此不建议自动替换正式模型。

## 数据与协议

- 使用 B-03D 同一批 50 张 `holdout100` 图片和同一批 705 个七类 GT 框。GT 来自 `Feng1909/bdd100k_voc_labels` 的 2020 Detection VOC 转换镜像；官方 `det_val.json` 仍未直取。
- `rider`、`traffic sign` 被排除，`pedestrian -> person`；不把 `rider` 合并为 `person`。
- 板端低阈值推理：`conf=0.001`、NMS IoU `0.45`、输入 `512x288 RGB UINT8 NHWC`、输出 `[1,4,3024] + [1,10,3024]`。离线匹配 IoU 为 `0.5`。
- 该 50 张图片是反复使用的历史诊断样本，所有指标只用于候选筛选，不能当作独立最终测试成绩。

## 量化原因检查

- **预处理：** 已核对 RGB、letterbox、`512x288`、板端 NHWC UINT8 以及 `mean=0/std=255`。B-03C 的 PyTorch/ONNX 对照为平均 IoU 约 0.999，未发现能解释大幅退化的颜色或坐标映射 Bug。
- **校准：** 当前校准集是 76 张非冻结道路视频画布（73+3），采用 RGB/NCHW UINT8 数组，未使用这 50 张评测图，也没有已知文件名重叠。它与 BDD holdout 的采集分布仍可能不同，样本数也有限，因此校准代表性是未消除的风险。
- **量化：** 原 INT8 相对旧的 FP32 `conf=0.25` 参考曾显示行人和交通灯下降；但该 FP32 缓存没有 `conf=0.001` 低阈值结果，不能直接做完整 AP 对比。KL 在完全相同预处理和校准素材下提升了 AP/Precision，说明量化范围搜索确有影响；现有证据不足以把退化唯一归因于预处理、校准或量化本身，最合理判断是**量化误差与校准代表性共同作用**。

有限优化尝试：`normal + channel` 为原基线；`kl_divergence + channel` 构建成功。`mmse` API 可用但在 Toolkit2 2.3.2 上进入逐层搜索，运行估计明显超出本轮预算，已停止且未生成候选。Toolkit2 暴露 `auto_hybrid`/`quantized_hybrid_level`，本轮没有启动第二个混合精度构建，避免在没有明确收益证据时扩大搜索。

## 明确回答

1. **调整阈值能减少多少 FP，损失多少 TP？** 原模型从 `0.25 -> 0.45`：FP `198 -> 48`（-150），TP `308 -> 222`（-86）。推荐 KL `0.35` 相对 KL `0.25`：FP `144 -> 62`（-82），TP `298 -> 259`（-39）。
2. **退化主要来自哪里？** 已排除明显预处理/解码错误；量化和校准代表性都可能贡献，当前实验不能唯一归因。KL 同校准重建后的改善说明量化范围算法是有效杠杆。
3. **新 RKNN 是否明显改善行人和交通灯？** 行人改善明显（TP 7->8、FP 10->2、Recall 20.59%->23.53%）；交通灯没有改善（Recall 18.30%->11.11%，但 FP 68->33）。
4. **新模型是否仍比原 YOLO11n 的 21.616 Pipeline FPS 快？** 是。KL 为 26.109 FPS，约快 20.8%；原 BDD INT8 为 25.620 FPS。两者均来自 RK3566 短时测试，不是 PC 速度。
5. **推荐保留原 INT8、采用改进 INT8，还是暂时停止优化？** **暂时保留原正式模型，保留 KL 作为独立候选并停止本轮优化。** KL 的整体 AP/Precision/FP/FPS 更好，但交通灯召回下降，且样本是历史 50 图；不能自动替换。继续保留 Traffic-Light Specialist。

**最终状态：PARTIAL。** 已完成可复现的阈值筛选、一个成功的量化候选和 RK3566 短测；官方 `det_val.json`、更大未参与筛选的 GT 集、完整 FP32 低阈值缓存以及混合精度候选仍缺失。
